## Demo「未过 Admission 不能升 accepted」

最短可复现路径（不需要模型、不启动 TUI）：

```bash
bun test src/mission/skills-routing.test.ts -t "missing holdout cannot promote"
bun test src/evidence/method-admission.test.ts -t "missing protected holdout"
```

期望：

1. 有效性可以过（官方样例 + 对抗子集上“effective”）。
2. **没有 protected holdout → Admission `fail`，`admitted: false`。**
3. `attemptSkillAccepted` 后 Skill 仍是 `candidate`，`defaultContextPointers` 为空。
4. `/skills` 目录文案写明 accepted 升级需要 Admission；缺 holdout 拒绝。

对照正路径（过门才能进默认上下文）：

```bash
bun test src/mission/skills-routing.test.ts -t "Admission pass is required"
```

显式挂点（inconclusive ≠ pass）：

```bash
bun test src/mission/skills-routing.test.ts -t "validity hang"
```

回滚：`demoteSkill` / writeback `rollback()` 把已接纳切片打成 `demoted`，离开默认上下文。

## 打开的缝 / 未开的缝

- **打开**：`evaluateExperimentValidity`、`evaluateMethodAdmission`、`MethodWritebackSession`（propose → regression → admit/rollback，一次一片）、`attemptSkillAccepted` / `demoteSkill`。
- **未开（有意）**：Skills **文件体**写回仍是 `writeback not opened — read-only shell`；BUD；SEA；DeployArena；AtCoder 真交；`#40`；默认 `fixed_uct` 不变。
- **未改**：Kill-test / T48 / hang / Broker 谓词；Elite ≠ Promotion / Admission key。
