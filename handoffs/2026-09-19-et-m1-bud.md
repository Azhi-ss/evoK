# ET-M1-BUD handoff — 超预算拒 continue / writeback

| field | value |
|-------|--------|
| **ticket** | #144 · 晋级门 / evidence |
| **slice** | Budget Gate reserve → settle + continue / writeback refuse + optional Method Improvement sub-cap |
| **authority** | evidence owns the ledger; mission `/research continue` and Skills accepted writeback only hook a `BudgetDecision` |

## Demo「超预算拒」

最短可复现路径（不需要模型、不启动 TUI）：

```bash
bun test src/evidence/budget-gate.test.ts -t "over-cap reserve refuses"
bun test src/mission/research-entry.test.ts -t "over-budget or unreserved"
```

期望：

1. `reserve` 超过 Mission total → `outcome: "refuse"`, `reason: "over_budget"`，账本不占额。
2. 没有 open reserve → `authorize("continue")` / `authorize("writeback")` 为 `unreserved`。
3. `/research continue` 传入该 `BudgetDecision` → `ResearchContinueRejectedError`，**不写入** skeleton experiment。
4. `settle` 没有对应 reserve → 失败且 `consumed` 仍为 0。

对照正路径（先预留再继续）：

```bash
bun test src/mission/research-entry.test.ts -t "reserved BudgetDecision does not replace"
```

写回正交（预算过 ≠ Admission 过）：

```bash
bun test src/evidence/budget-gate.test.ts -t "budget pass is not Admission"
bun test src/mission/skills-routing.test.ts -t "Admission pass still cannot write"
```

方法改进子上限：

```bash
bun test src/evidence/budget-gate.test.ts -t "capped separately"
```

## 打开的缝 / 未开的缝

- **打开**：`BudgetLedger.reserve` / `settle` / `authorize`、`evaluateBudgetAuthorization`；`continueResearch({ budget })`；`attemptSkillAccepted(..., budget)`；`MethodWritebackSession.admit(admission, budget)`。
- **未开（有意）**：SEA；Skills **文件体**写回仍是 `writeback not opened — read-only shell`；DeployArena；AtCoder 真交；`#40`；默认 `fixed_uct` 不变。
- **未改**：Kill-test / T48 / hang / Broker 谓词；EXP Admission 谓词；MissionRecord 运营记账（`mission-start` reserveCost）；Elite ≠ Promotion / Admission / Budget key。

## Operator 可见

`evok /skills` 目录文案写明 writeback 还要 Budget Gate reserve；超预算或未预留拒绝；预算过不是 Admission 过。
