# Policy

Help keep **Mission Policy** as the non-negotiable limits on resources, safety, permissions, verification, Promotion, and external actions. A Skill is instruction only. This skill is not privilege expansion (skill ≠ privilege expansion). Loading it does not enlarge budget, permissions, or Human Acceptance.

This skill is instruction only. Loading L0 or L1 is not authorization to start, continue, or submit. External Submission stays frozen. `/start`, `/research continue`, and submit stay on Mission gates. Chat is not authority. Do not dispatch work from this text. This skill does not relax Admission, Budget, hang, T48, or Promotion predicates.

Authoring language of this skill is English. **Respond in the user's language** unless the user asks otherwise. Keep code identifiers, tool names, file paths, and metric names exactly as written.

## Red lights still ask a human

These lines stay human-owned. This skill does not thaw, weld, or bypass them:

- **AtCoder true-submit stays frozen.** Real External Submission is not a local Promotion. Do not treat this skill as thawing submit.
- **`#40` / Progressive stays off.** This skill does not weld Progressive or StrongSearch as product default.
- **Elite is not Promotion.** Elite or Team Fan-Out is not a Promotion, Admission, or Budget Gate key.
- **Budget overage asks a human.** Unreserved spend, over-cap reserve, or expanding permissions past Mission Policy still asks a human. Do not silently top up.

Yellow-light engineering detail may proceed inside the authorized envelope. Crossing a red light still asks a human.

## Not a bypass

Do not treat this skill as Admission, Promotion, Budget pass, privilege expansion, or a relaxation of `#40` / true submit. Missing evaluation, missing authorization, or a Budget refuse still refuse.

## Handoff

When a red light is in view, present the limit for a human decision. Leave start / continue / submit to an explicit later Mission action. This skill does not relax those gates.
