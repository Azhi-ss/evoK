# 预注册修正：搜索树历史块的截断

日期：2026-10-23。适用范围：harness-opt 在 `--search-tree-from-round` 打开之后，写进 gap-finder 和 innovator prompt 的搜索树历史块。不新增 `pre-round1.json` 的签名字段。搜索树仍然默认关闭。没打开时，预注册文件跟以前一样。

这份修正替换此前「摘要行本身超过 24000 字就报错」的规则。上限仍然是 24000 字。

## 摘要行

每一轮的每个候选先写成一行。旋钮只列有变化的键，格式是 `key: old→new`（旧值来自该轮 `baseline/config.json`，新值来自该候选自己的 config）。没变化的键不写。

critic 的原因、ranker 的原因、以及每一道门的原因，各截到 120 字。一行的目标长度不超过 400 字。先缩短评语，再缩短门原因，再缩短旋钮，使整行落在这个长度里。

reward 和 accept/reject 只写在这一轮真正评过的那个候选上。其余候选写 `reward=not evaluated` 和 `verdict=not evaluated`。

## 放不下时怎么退化

历史块的 JSON 正文（`summaries` 与 `details`）最多 24000 字。这段函数不抛错。有历史时，prompt 里至少留下一条，不会是 0 条。

顺序固定：

1. 放得下时，最近一轮保留全文详情，更早的轮次只有摘要行。
2. 超出 24000 时，先按整条丢掉最近一轮的详情，从最后一条开始。不从字符串中间截，不拆开 JSON。
3. 丢掉详情后仍然超出，就把最早的轮次收成一行。这一行是该轮最优候选（真正评过的那个，否则是 ranker 选中的那个）、它的 reward，再加上 `other N rejected`。从最老的一轮开始收，收到放得下为止。较新的轮次仍保留每个候选一行。
4. 每一轮都已收成一行却还超出时，丢掉最老的那一行，直到放得下。最新的一轮保留。

规则原文接在 JSON 后面。这段文字在角色 prompt 里，计入 innovator 单次上限和只读 3000 万上限。
